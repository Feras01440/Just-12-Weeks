# Milestone Gates

**Status:** Active. Companion to [delivery-roadmap.md](delivery-roadmap.md) — this file is the checklist actually used at each gate. A gate passes only when every item is ticked or explicitly waived by the founder in the decision log. Waivers name the risk accepted.

## Gate 0 → 1 : Foundation accepted, validation may start

- [ ] Founder directions D-001–D-004 recorded and reflected consistently across docs *(done 26 Jul 2026; verified by cross-doc audit)*
- [ ] Remaining open questions (per open-decisions register) answered or explicitly delegated
- [ ] Source audit complete; corrections applied; no load-bearing claim rests on an unsupported source
- [ ] Stage 1A public-evidence synthesis delivered and reviewed
- [ ] Passive validation system approved for publication (Gate B go; copy claims-policy compliant)
- [ ] Gate B spend authority confirmed (≤£300 cumulative, D-010)

## Gate 1 → 2 : Evidence supports proceeding

- [ ] Passive-system thresholds read on sufficient organic volume (or documented shortfall + plan); per-band signal reported where survey volume allows
- [ ] Every pre-registered proceed/revise/stop threshold has an evidenced verdict
- [ ] D-009 escalation checks performed; any fired trigger resolved (targeted interviews done per pack) or explicitly accepted open
- [ ] Go / pivot / stop recommendation written (gate pack); founder decision recorded
- [ ] Q1 (flagship launch category) decided on evidence
- [ ] Q2 pattern emphasis confirmed or revised

## Gate 2 → 3/4 : Product architecture approved

- [ ] PRD approved (guidance-first requirements G1–G10 included as acceptance criteria)
- [ ] MVP scope + non-goals signed; scope fits Q9 budget reality
- [ ] Programme engine spec approved; all four archetypes pass the paper test (a sample week of each archetype expressed in the schema without distortion)
- [ ] Progress-evidence model approved; Q12A answered
- [ ] Content governance framework approved; reviewer for flagship programme identified and costed
- [ ] Success metrics + analytics spec approved (privacy review passed)
- [ ] Week-13 model chosen (Q13)

## Gate 3 : Brand direction chosen

- [ ] Three genuinely distinct territories presented (distinctness test: a stranger can describe each in one sentence without mentioning the others)
- [ ] Each territory assessed for broad-adult-audience fit and accessibility (D-001)
- [ ] Founder selects one (or one fusion iteration)
- [ ] Name shortlist screened for trademark conflicts incl. *The 12 Week Year* proximity (Q10)
- [ ] Anti-generic audit checklist adopted as a standing design instrument

## Gate 4 → 5 : Flows approved on paper

- [ ] All 23 core flows documented with every state (error/empty/offline/permission/expiry)
- [ ] Every flow passes experience-principles G1–G5 on paper
- [ ] No flow requires input that fails the four-job purposefulness test
- [ ] Recovery flows (1 day / several days / long absence) reviewed word-by-word against the blame lexicon
- [ ] Accessibility annotations present on every wireframe

## Gate 5 → 6 : Prototype evidence supports building

- [ ] 10–12 usability sessions run, every age band n≥2, including low-digital-confidence participants
- [ ] G6 regime met (≥80% overall, no cohort majority failing); G9 paywall comprehension 5/5
- [ ] 200%-text and reduced-motion sessions completed without task failure
- [ ] Findings fed back into flows; material changes re-tested
- [ ] Founder approves build scope against evidence

## Gate 6 → 7 : Technical foundation proven

- [ ] ADR-001 (framework) approved by founder — no longer provisional
- [ ] Walking skeleton runs on iOS + Android reference devices (incl. low-end Android from device matrix)
- [ ] Sandbox purchase, restore, cancellation and account deletion work end-to-end
- [ ] Analytics consent gating verified (no events before consent)
- [ ] CI/CD produces installable builds on every commit
- [ ] Security requirements baseline implemented (transport, storage, auth)

## Gate 7 → 8 : Feature-complete against scope

- [ ] Every MVP scope line demo'd against its acceptance criteria, including offline/error/large-text/dark-mode/reduced-motion states
- [ ] Zero scope additions without decision-log entry
- [ ] Flagship programme content complete, reviewer-signed, citations in place
- [ ] Experience-principle release blockers (G1–G10) all green

## Gate 8 → 9 : Quality bar met

- [ ] Test strategy executed; no known data-loss or billing defects
- [ ] Accessibility audit passed (see accessibility-test-plan)
- [ ] Performance plan budgets met on low-end Android reference device
- [ ] Subscription lifecycle edge cases (refund, expiry, restore, plan change, offline grace) all pass
- [ ] Known-issues list triaged; nothing release-blocking open

## Gate 9 → 10 : Beta evidence supports launch

- [ ] ≥4 real weeks of beta with 30–80 target-audience users across age bands
- [ ] Pre-agreed thresholds met (activation, D1/D7, weekly-review completion, recovery-flow return rate) or documented decision to iterate
- [ ] Drop-off interviews conducted; top-3 causes addressed
- [ ] Billing integrity verified with real sandbox/TestFlight cohorts

## Gate 10 → 11 : Store-ready

- [ ] Privacy labels + Data safety form accurate against data inventory
- [ ] Account deletion (in-app + Google web link) verified live
- [ ] Subscription disclosures verified against `05-commercial/subscription-requirements.md`
- [ ] Store copy and screenshots pass claims policy (no outcome promises)
- [ ] Both stores approved

## Gate 11 → 12 : Launched and measured

- [ ] Phased rollout completed to 100% with crash-free and billing-integrity thresholds held
- [ ] Day-7 launch report delivered
- [ ] Measurement cadence (weekly metrics, quarterly strategy) scheduled

*Standing rule:* any gate may be revisited if its evidence is later invalidated; passing a gate is a decision-log entry, not a ceremony.
